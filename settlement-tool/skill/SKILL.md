# 하이포스 업체 정산 자동화

춘천지역먹거리직매장(사용자)이 하이포스에서 매달 뽑는 "전산원본" 엑셀 한 장으로,
출하업체(약 50~60곳) 정산에 필요한 문서 두 종류를 자동으로 만든다.

- **결과물1** — 정산 총액 증빙 요약표. 사용자가 4년째 써온 고정 양식이므로
  컬럼 구성·순서를 절대 바꾸지 않는다. 결과물1은 그 자체로 증빙자료이자,
  결과물3을 만드는 기초 데이터이기도 하다.
- **결과물3** — 업체별로 세금계산서 발행을 요청하는 표. 화면 일부를 캡처해서
  업체 메일에 그대로 첨부하는 용도라서, 업체 1곳당 표 블록이 세로로 이어지는
  형태를 유지한다.

이 스킬은 실제 하이포스 파일(전산원본 + 기존 결과물1/결과물3 예시) 4개를 놓고
사용자와 함께 검증하며 만들어졌다. 아래 규칙들은 전부 그 검증 과정에서 나온
결론이니 임의로 바꾸지 말고, 바꿔야 할 이유가 생기면 사용자에게 먼저 확인한다.

## 실행 순서

1. **이번 달 전산원본 파일을 받는다.** 사용자가 이미 첨부했다면 그걸 쓰고,
   없다면 요청한다. 시트명은 `수수료매출내역(거래처별)`로 고정되어 있어야
   스크립트가 읽을 수 있다 (하이포스 내보내기 기본값이라 보통 문제없다).

2. **작성일자와 직매장 대표자명을 확인한다.** 결과물3의 안내문구에 들어가는
   두 값이다. 사용자가 이미 알려줬으면 쓰고, 없으면 "이번 달 작성일자(예:
   8월 31일)와 직매장 대표자명을 알려주세요"라고 물어본다.

3. **결과물1을 생성한다.**
   ```
   python scripts/generate_report1.py <전산원본.xls> <출력경로>/결과물1_M월_매출정리.xlsx
   ```

4. **결과물3을 생성한다.** (결과물1의 출력 파일을 입력으로 받는다)
   ```
   python scripts/generate_report3.py <결과물1_M월_매출정리.xlsx> <출력경로>/결과물3_M월_세금계산서요청.xlsx
   ```
   생성 직후 `generate_report3.py`가 실행 로그에 찍는 "N개 업체 블록"의 N이
   결과물1의 실제 업체 수(하이포스 합계행 제외)와 같은지 확인한다.

5. **두 파일을 사용자에게 전달한다.** `SendUserFile` 등 파일 전달 도구가
   있으면 그걸로 보내고, 결과물3의 작성일자(B1)/대표자명(B2) 칸은 필요하면
   엑셀에서 바로 고칠 수 있다는 점을 알려준다.

의존성: `pandas`, `openpyxl`, (하이포스 원본이 구버전 `.xls`면) `xlrd`.
세 패키지가 없으면 `pip install pandas openpyxl xlrd`로 설치한다.

## 반드시 지켜야 할 두 가지 계산 규칙

이 두 규칙은 사용자와 함께 실제 데이터로 검산해서 확정한 것이다. 이유를
모르고 지나치면 다음에 스크립트를 고칠 때 실수로 되돌리기 쉬우니 왜
이렇게 하는지 적어둔다.

### 1. 과세공급가액/부가세는 하이포스 값을 그대로 베끼지 않고, 과세지급액(총액) 기준으로 역산한다

하이포스 원본은 공급가액과 부가세를 각각 따로 반올림해서 저장하는데, 이
둘을 그냥 합치면 가끔 총액(과세지급액)과 1원이 어긋난다. 실제로 "재헌식품"
사례에서 원본은 공급가액 1,482,136 / 부가세 148,214였는데, 사용자가 예전에
받은 결과물1에는 1,482,137 / 148,213로 되어 있었다 — 총액은 똑같이
1,630,350인데 내부 배분만 1원 흔들린 것이다.

그래서 `generate_report1.py`는 공급가액/부가세를 원본에서 복사하지 않고,
**과세지급액(총액)을 유일한 기준값**으로 삼아 매번 똑같이 계산한다.

```python
supply = round(taxed_total / 1.1)      # 과세공급가액
vat = taxed_total - supply             # 부가세 = 총액 - 공급가액
```

이렇게 하면 총액은 항상 원본과 정확히 일치하면서, 공급가액/부가세 배분은
매번 같은 규칙으로 결정되어 흔들리지 않는다.

### 2. 하이포스가 붙이는 합계행은 결과물1엔 남기고, 결과물3에선 제외한다

전산원본 맨 마지막 줄은 실제 업체가 아니라 하이포스가 자동으로 붙이는
합계행이다. 코드와 사업자번호 칸이 비어 있고, **거래처명 칸에 업체 이름
대신 업체 수(예: "57")가 숫자로 들어가 있는 게 특징**이다. 다른 값들은
전부 열별 합계다.

- **결과물1에서는 이 행을 그대로 둔다.** 4년째 써온 기존 양식이 이 합계행을
  포함하고 있어서, 형식을 그대로 유지하려면 이 행도 유지해야 한다.
- **결과물3에서는 이 행을 제외한다.** 이건 세금계산서를 요청할 "업체"가
  아니라 그냥 합계 숫자라서, 이 행으로 안내문구/표 블록을 만들면 존재하지
  않는 업체 앞으로 세금계산서 발행을 요청하는 이상한 메일 자료가 나온다.
  `generate_report3.py`는 사업자번호가 비어있는 행을 걸러내는 방식으로
  이걸 제외한다 (`load_report1`의 필터 참고).

## 결과물3 안내문구 커스터마이징

`generate_report3.py`의 `build_block()` 안, `notice_cell.value`에 들어가는
수식이 실제 이메일에 표시되는 안내문구를 결정한다. 지금은:

```
공급받는자 : 춘천지역먹거리직매장 (대표자 {대표자명})   /   {작성일자}자로 발행 해주세요.
```

형태로 되어 있다. 이건 사용자와 상의해서 정한 초안이니, 사용자가 문구를
바꿔달라고 하면 이 f-string만 고치면 58개(또는 매달 다른 개수) 업체
블록에 전부 한 번에 반영된다 — 블록마다 따로 고칠 필요 없다.

## 검증 방법 (수정할 때마다 확인)

이 환경에서는 LibreOffice 기반 수식 재계산(`recalc.py`)이 간헐적으로
작동하지 않을 수 있다. 그럴 땐 순수 파이썬 수식 평가 라이브러리로 대체
검증한다:

```bash
pip install -q formulas
python3 -c "
import formulas
m = formulas.ExcelModel().loads('결과물3_생성.xlsx').finish()
sol = m.calculate()
errors = [k for k,v in sol.items() if any(e in str(getattr(v,'value',v)) for e in ['#REF!','#NAME?','#VALUE!','#DIV/0!','#N/A','#NULL!','#NUM!'])]
print('formula errors:', len(errors))
"
```

`openpyxl`로 셀에 빈 문자열(`""`)을 쓰면 `<is>` 태그 없는 깨진
`inlineStr` 셀이 생겨 LibreOffice/Excel이 파일 자체를 못 여는 경우가
있었다 — 빈 칸은 아예 값을 쓰지 않고 비워둔다 (`ws.cell(...)` 자체를
호출하지 않음). 단일 셀에 `merge_cells`를 걸어도(범위가 셀 하나뿐인
병합) 같은 증상이 난다 — 병합은 항상 2개 이상의 셀 범위에만 사용한다.

## 매달 반복할 때

전산원본 파일만 새로 받으면 위 4~5단계 그대로 다시 실행하면 된다. 업체
수나 컬럼 구성이 크게 바뀌지 않는 한 스크립트 수정은 필요 없다. 하이포스
쪽에서 시트명이나 컬럼 순서를 바꿨다면 `generate_report1.py`의
`COLUMN_MAP`을 그에 맞게 고쳐야 한다.
